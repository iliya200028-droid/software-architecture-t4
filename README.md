# Домашняя работа № 4. Основы архитектуры ПО

## Tomcat: сервлеты, cookies и сессии

Я разработал учебное веб-приложение UserAuthApp. Оно демонстрирует жизненный цикл сервлета, обработку GET и POST, проверку учётных данных, создание cookie и хранение данных пользователя в HTTP-сессии.

## Что реализовано

| Требование | Реализация |
|---|---|
| Инициализация пользователей в init | LoginServlet.init(): ConcurrentHashMap с именами и паролями |
| Форма входа | LoginServlet.doGet(), адрес /login |
| Проверка данных и перенаправление | LoginServlet.doPost(), переход на /welcome |
| Приветствие и кнопка | WelcomeServlet.doGet() |
| Создание и чтение cookie | Cookie username создаётся при входе и читается в WelcomeServlet |
| Создание сессии | LoginServlet сохраняет user и loginTime |
| Информация из сессии | UserInfoServlet.doGet(), адрес /userinfo |
| Регистрация, пункт К3 | Дополнительный RegistrationServlet, адрес /register |

В основной части задания названы три сервлета, а в критериях К3 упомянута регистрация. Поэтому к трём обязательным сервлетам добавлена регистрация. Формы генерируются в doGet, как требует основная часть задания.

## Среда

- JDK 17.
- Apache Tomcat 10.1.x, Jakarta Servlet API 6.0.
- Maven 3.9.x для сборки проекта из исходников.
- IntelliJ IDEA для редактирования и запуска Maven.

Проект использует jakarta.servlet. Tomcat 9 с javax.servlet для этого проекта не подходит. Официальная документация: https://tomcat.apache.org/migration-10.1.html

## Быстрый запуск готового WAR в Windows

1. Установите JDK 17 и Apache Tomcat 10.1.x. Укажите JAVA_HOME на папку JDK.
2. Скопируйте dist/UserAuthApp.war в папку webapps вашего Tomcat.
3. Откройте командную строку в папке bin Tomcat и выполните `catalina.bat run`.
4. Откройте http://localhost:8080/UserAuthApp/login.
5. Введите имя `ilya` и пароль `12345`. Вторая учётная запись: `student` / `java123`.
6. Нажмите «Информация о пользователе» для просмотра данных сессии.

В Linux/macOS сервер запускается командой `sh bin/catalina.sh run` из папки Tomcat. Готовый WAR уже содержит скомпилированные классы; отдельный запуск main не нужен.

## Открытие и сборка в IntelliJ IDEA

1. Распакуйте архив и откройте папку UserAuthApp через File → Open.
2. Подтвердите импорт Maven-проекта, если IDEA его предложит.
3. В Project Structure выберите Project SDK 17.
4. Дождитесь загрузки Maven-зависимостей. Для первой сборки нужен интернет.
5. В окне Maven выполните Lifecycle → clean, затем package. Альтернатива при установленном Maven: `mvn clean package` в папке с pom.xml.
6. Скопируйте полученный target/UserAuthApp.war в webapps Tomcat и запустите сервер.

Запуск через внешний Tomcat не требует встроенной поддержки серверов приложений в IDEA. При повторном развёртывании остановите Tomcat, замените WAR и удалите только старую распакованную папку webapps/UserAuthApp, затем запустите Tomcat снова.

## Структура

Исходники находятся в src/main/java/ru/synergy/auth. Настройка веб-приложения — src/main/webapp/WEB-INF/web.xml. Maven при сборке помещает классы в WEB-INF/classes/ru/synergy/auth внутри WAR. Servlet API имеет scope provided: его предоставляет Tomcat.

- LoginServlet.java — init, doGet и doPost для входа.
- WelcomeServlet.java — чтение cookie и приветствие.
- UserInfoServlet.java — чтение данных сессии.
- RegistrationServlet.java — создание пользователя в общем хранилище.
- Html.java — HTML-оболочка, экранирование и проверка авторизации.
- CODE.txt — все исходники обычным текстом для просмотра и копирования.
- dist/UserAuthApp.war — готовый архив приложения.
- tests/smoke_test.py — HTTP-проверки на работающем сервере.
- TEST_RESULTS.txt — фактический результат проверки.

## Логика работы

LoginServlet загружается при старте приложения благодаря loadOnStartup = 1. Его init создаёт общее потокобезопасное хранилище и помещает его в ServletContext. RegistrationServlet использует то же хранилище; putIfAbsent не позволяет одновременно зарегистрировать одинаковые имена.

После успешного POST /login прежняя сессия аннулируется, создаётся новая сессия и cookie username со сроком жизни один час. Переход на /welcome выполняется перенаправлением. WelcomeServlet берёт имя из cookie; UserInfoServlet получает имя и время входа из сессии. Время бездействия сессии — 30 минут.

Защищённые страницы используют getSession(false): без авторизации посетитель возвращается к форме входа. Cookie username служит только для отображения и не предоставляет доступ. Если она удалена, приветствие сообщает об отсутствии cookie, а данные сессии остаются доступны. HTML-значения экранируются.

## Проверка вручную

1. Откройте /userinfo в приватном окне: должен произойти переход на /login.
2. Введите неверный пароль: появится сообщение об ошибке.
3. Войдите как ilya: появится приветствие с именем.
4. В инструментах разработчика браузера проверьте cookies username и JSESSIONID.
5. Перейдите к информации о пользователе: должны отображаться имя и время входа.
6. Зарегистрируйте нового пользователя и войдите под его именем.
7. Попробуйте повторную регистрацию того же имени: приложение сообщит, что имя занято.

Автоматическая проверка при запущенном Tomcat: `python tests/smoke_test.py`. Требуется Python 3, внешние Python-библиотеки не нужны. Проверка создаёт одного тестового пользователя в оперативной памяти.

## Ограничения учебного приложения

Пароли хранятся в Map в открытом виде в соответствии с условием; это демонстрационная реализация. Новые пользователи существуют до перезапуска приложения. Для реального сервиса нужны постоянное хранилище и хеширование паролей. Cookie username можно изменить на клиенте, поэтому она не используется как источник авторизации.
